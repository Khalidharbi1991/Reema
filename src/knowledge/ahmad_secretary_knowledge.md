## 2. Project Coordination & Workflow Management

### 2.1 SOP Generation Workflow
**Standard Workflow (12-24 day process):**
```
Phase 1: INITIATION (Day 1)
  Ahmad → Receive request from Khalid
  Ahmad → Create project tracking entry
  Ahmad → Brief Abdullah on requirements

Phase 2: RESEARCH (Days 2-4)
  Abdullah → Assign to Taif (Research)
  Abdullah → Assign to Mohammad (Standards) [parallel]
  Ahmad → Track progress, update Khalid

Phase 3: CONTENT CREATION (Days 5-10)
  Abdullah → Assign to Saad (Content)
  Abdullah → Assign to Layla (Data/BI) [parallel]
  Ahmad → Monitor milestone progress

Phase 4: QUALITY REVIEW (Days 11-14)
  Abdullah → Assign to Faisal (Review)
  Ahmad → Track quality score
  IF score < 85%: Return to Saad for revision
  IF score >= 85%: Proceed to formatting

Phase 5: FORMATTING (Days 15-17)
  Abdullah → Assign to Bee (Format)
  Ahmad → Track multi-format output

Phase 6: DELIVERY (Days 18-20)
  Ahmad → Package deliverables
  Ahmad → Submit to Khalid for final approval
  Ahmad → Deliver to client
  Ahmad → Archive project records
```

### 2.2 Task Assignment & Tracking
**Task States:**
- BACKLOG: Identified but not started
- ASSIGNED: Given to agent
- IN_PROGRESS: Agent working actively
- BLOCKED: Waiting on dependency or issue
- IN_REVIEW: Under quality review
- COMPLETED: Done and accepted
- CANCELLED: No longer required

## 3. Document Control & Records Management

### 3.1 Document Naming Convention
**Format:** `[Type]-[Category]-[Process]-[Version].[Extension]`

**Examples:**
- `SOP-ITIL-Incident_Management-v1.0.docx`
- `SOP-SEC-Workstation_Security_Patches-v1.0.pdf`
- `SOP-ITOM-Event_Management-v2.1.md`
- `RPT-QA-Quality_Review_Incident_Mgmt-v1.0.pdf`

**Type Codes:**
| Code | Type |
|------|------|
| SOP | Standard Operating Procedure |
| POL | Policy Document |
| RPT | Report |
| TPL | Template |
| CHK | Checklist |
| WKF | Workflow Document |

**Category Codes:**
| Code | Category |
|------|----------|
| ITIL | ITIL Core Processes |
| ITOM | IT Operations Management |
| ITAM | IT Asset Management |
| SEC | Security & Compliance |
| CUST | Custom Processes |

### 3.2 Version Control Protocol
**Semantic Versioning: MAJOR.MINOR**
- MAJOR (1.0, 2.0): Significant structural changes, new sections, major rewrites
- MINOR (1.1, 1.2): Content updates, corrections, additions within existing structure

**Version History Entry Format:**
| Version | Date | Author | Changes | Approved By |
|---------|------|--------|---------|-------------|
| 0.1 | [date] | Saad | Initial draft | - |
| 0.2 | [date] | Saad | Incorporated review feedback | - |
| 1.0 | [date] | Saad | Final approved version | Khalid |
| 1.1 | [date] | Saad | Minor corrections | Abdullah |

### 3.3 Document Lifecycle
```
DRAFT (v0.x)
  ↓ Author creates
IN REVIEW (v0.x)
  ↓ Faisal reviews, score >= 85%
APPROVED (v1.0)
  ↓ Khalid approves
PUBLISHED (v1.0)
  ↓ Distributed to stakeholders
ACTIVE (v1.x)
  ↓ In use, minor updates applied
UNDER REVISION (v2.0-draft)
  ↓ Major update triggered
ARCHIVED
  ↓ Superseded by new version
RETIRED
  No longer applicable
```
