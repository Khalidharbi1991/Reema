### ISO 27001 Implementation Process

#### Phase 1: Preparation (Months 1-2)
- Obtain management commitment
- Define scope and boundaries
- Conduct gap analysis
- Allocate resources
- Establish project team

#### Phase 2: Risk Assessment (Months 3-4)
- Identify information assets
- Identify threats and vulnerabilities
- Assess risks (likelihood × impact)
- Determine risk appetite
- Create risk treatment plan

#### Phase 3: Implementation (Months 5-9)
- Implement selected Annex A controls
- Create policies and procedures
- Deploy technical controls
- Conduct training and awareness
- Document everything

#### Phase 4: Internal Audit (Month 10)
- Conduct internal ISMS audit
- Identify non-conformities
- Implement corrective actions
- Management review

#### Phase 5: Certification Audit (Months 11-12)
- Stage 1: Documentation review
- Stage 2: Implementation audit
- Address any findings
- Receive certification

#### Post-Certification: Maintenance
- Annual surveillance audits (Years 1 & 2)
- Recertification audit (Year 3)
- Continuous monitoring and improvement

### ISO 27001 Risk Assessment Methodologies

#### Quantitative Risk Assessment
- **Asset Value** × **Threat Probability** × **Vulnerability** = **Risk**
- Expressed in monetary terms
- More objective but requires more data

#### Qualitative Risk Assessment
- Uses scales (Low, Medium, High)
- Faster to conduct
- More subjective

#### Risk Treatment Options
1. **Mitigate** - Implement controls to reduce risk
2. **Accept** - Accept risk if within appetite
3. **Avoid** - Eliminate the activity causing risk
4. **Transfer** - Insurance or outsource

## 3. COBIT 2019 - IT GOVERNANCE FRAMEWORK

### Overview
**COBIT 2019** - Control Objectives for Information and Related Technologies
**Owner:** ISACA (Information Systems Audit and Control Association)
**Purpose:** IT governance and management framework
**Focus:** Aligning IT with business goals

### COBIT 2019 Framework Structure

#### Core Components

### 1. COBIT Governance System Principles (6 Principles)

**Principle 1:** Provide Stakeholder Value
- Every enterprise exists to create value for stakeholders
- Balance benefits, risk, and resources

**Principle 2:** Holistic Approach
- Multiple interacting components make up a governance system
- Consider all factors collectively

**Principle 3:** Dynamic Governance System
- One size does not fit all
- Tailor to enterprise context

**Principle 4:** Governance Distinct from Management
- Governance: Ensures objectives achieved, risks managed
- Management: Plans, builds, runs, monitors activities

**Principle 5:** Tailored to Enterprise Needs
- Custom design based on goals and context
- Use design factors for tailoring

**Principle 6:** End-to-End Governance System
- Covers enterprise end-to-end
- Integrates all functions and processes

### 2. COBIT Governance and Management Objectives

#### 5 Governance Objectives (EDM)
**EDM01** - Ensure Governance Framework Setting and Maintenance
**EDM02** - Ensure Benefits Delivery
**EDM03** - Ensure Risk Optimization
**EDM04** - Ensure Resource Optimization
**EDM05** - Ensure Stakeholder Engagement

#### 4 Management Domains (40 Objectives)

### 3. COBIT Design Factors (11 Factors)

Design factors help tailor COBIT to enterprise needs:

1. **Enterprise Strategy** - Mission, vision, values
2. **Enterprise Goals** - What enterprise wants to achieve
3. **Risk Profile** - Risk appetite and risk landscape
4. **I&T Issues** - Current problems and concerns
5. **Threat Landscape** - External threats
6. **Compliance Requirements** - Laws and regulations
7. **Role of IT** - Support, factory, strategic, turnaround
8. **Sourcing Model** - Insourced, outsourced, hybrid
9. **IT Implementation Methods** - Agile, DevOps, traditional
10. **Technology Adoption Strategy** - Early adopter, fast follower, cautious
11. **Enterprise Size** - Large, medium, small

### COBIT Performance Management

#### Goals Cascade
1. **Enterprise Goals** (13 goals across 5 BSC dimensions)
2. **Alignment Goals** (14 goals across 4 dimensions)

#### Balanced Scorecard (BSC) Dimensions
- **Financial** - Financial performance

### COBIT Capability Levels (0-5)

**Level 0:** Incomplete - Process not implemented
**Level 1:** Performed - Process achieves its purpose
**Level 2:** Managed - Process is managed
**Level 3:** Established - Process uses defined standard
**Level 4:** Predictable - Process operates within limits

**P8.1** - Monitoring and enforcement

### SOC 2 Report Types

#### Type I Report
- **Scope:** Point in time
- **Tests:** Design of controls
- **Question:** Are controls properly designed?
- **Timeline:** 1-3 months to prepare
- **Purpose:** Initial assessment

#### Type II Report
- **Scope:** Period of time (typically 6-12 months)
- **Tests:** Design AND operating effectiveness
- **Question:** Are controls working as intended?
- **Timeline:** 6-12 months of evidence
- **Purpose:** Ongoing assurance

### SOC 2 Audit Process

#### Phase 1: Readiness Assessment (Month 1-2)
- Gap analysis
- Identify applicable TSC
- Document controls
- Implement missing controls

#### Phase 2: Implementation (Month 3-6)
- Establish policies and procedures
- Implement technical controls
- Train personnel
- Begin evidence collection

#### Phase 3: Pre-Audit (Month 7)
- Internal audit
- Fix identified gaps
- Test controls
- Collect evidence

#### Phase 4: Audit (Month 8-9)
- Auditor performs fieldwork
- Review documentation
- Test controls
- Interview personnel

#### Phase 5: Report Issuance (Month 10)
- Draft report review
- Address findings
- Final report issued
- Report distribution

### SOC 2 vs ISO 27001 Comparison

| Aspect | SOC 2 | ISO 27001 |
|--------|-------|-----------|
| Origin | United States (AICPA) | International (ISO) |
| Focus | Trust services | Information security |
| Certification | No certification, just report | Certification available |
| Prescriptive | Less prescriptive | More prescriptive |
| Customization | High - choose TSC | Medium - must implement all applicable |
| Audience | Service providers | Any organization |
| Public | Private report | Certificate is public |
| Renewal | Annual audit | Annual surveillance, 3-year recert |

## 5. REGULATORY COMPLIANCE FRAMEWORKS

### GDPR (General Data Protection Regulation)

#### Overview
- **Effective:** May 25, 2018
- **Scope:** EU residents' data (regardless of org location)
- **Penalties:** Up to €20 million or 4% of global revenue

#### Seven Principles
1. **Lawfulness, Fairness, Transparency** - Legal basis for processing
2. **Purpose Limitation** - Specific, legitimate purposes only
3. **Data Minimization** - Adequate, relevant, limited
4. **Accuracy** - Keep data accurate and up to date
5. **Storage Limitation** - Retain only as long as necessary
6. **Integrity and Confidentiality** - Security measures
7. **Accountability** - Demonstrate compliance

#### Data Subject Rights
- Right to access
- Right to rectification
- Right to erasure ("right to be forgotten")
- Right to restrict processing
- Right to data portability
- Right to object
- Rights related to automated decision-making

#### GDPR Requirements for IT
- Data Protection Impact Assessments (DPIA)
- Data Protection Officer (DPO) - if required
- Privacy by Design and Default
- Breach notification (72 hours)
- Processor agreements
- Records of processing activities
- International data transfers (adequacy decisions)

### HIPAA (Health Insurance Portability and Accountability Act)

#### Overview
- **Effective:** 1996 (Privacy Rule 2003, Security Rule 2005)
- **Scope:** US healthcare entities and business associates
- **Penalties:** Up to $1.5 million per violation category per year

#### HIPAA Rules

**Privacy Rule**
- Protected Health Information (PHI) rights
- Minimum necessary standard
- Notice of Privacy Practices
- Patient authorization requirements

**Security Rule**
- Administrative Safeguards (18 standards)
- Physical Safeguards (9 standards)
- Technical Safeguards (11 standards)

**Breach Notification Rule**
- Notify affected individuals (60 days)
- Notify HHS
- Notify media (if >500 affected)

#### HIPAA Security Rule Categories

**Administrative Safeguards:**
- Security Management Process
- Assigned Security Responsibility
- Workforce Security
- Information Access Management
- Security Awareness and Training
- Security Incident Procedures
- Contingency Plan
- Evaluation
- Business Associate Contracts

**Physical Safeguards:**
- Facility Access Controls
- Workstation Use
- Workstation Security
- Device and Media Controls

**Technical Safeguards:**
- Access Control
- Audit Controls
- Integrity Controls
- Person or Entity Authentication
- Transmission Security

### PCI-DSS (Payment Card Industry Data Security Standard)

#### Overview
- **Owner:** PCI Security Standards Council
- **Scope:** Organizations handling credit card data
- **Levels:** Based on transaction volume (Level 1-4)

#### 12 Requirements (6 Goals)

**Goal 1: Build and Maintain Secure Network**
1. Install and maintain firewall
2. Don't use vendor defaults

**Goal 2: Protect Cardholder Data**
3. Protect stored cardholder data
4. Encrypt transmission over public networks

**Goal 3: Maintain Vulnerability Management**
5. Protect against malware
6. Develop secure systems and applications

**Goal 4: Implement Strong Access Control**
7. Restrict access by business need-to-know
8. Identify and authenticate access
9. Restrict physical access

**Goal 5: Monitor and Test Networks**
10. Track and monitor network access
11. Test security systems and processes

**Goal 6: Maintain Information Security Policy**
12. Maintain policy addressing information security

#### PCI-DSS v4.0 (Effective March 2024)
- Transition period until March 2025
- Enhanced authentication requirements
- Expanded scope for e-commerce
- Updated encryption requirements
- New requirements for service providers

### SOX (Sarbanes-Oxley Act)

#### Overview
- **Effective:** 2002
- **Scope:** US public companies
- **Focus:** Financial reporting accuracy

#### IT-Relevant Sections

**Section 302:** Corporate Responsibility for Financial Reports
- CEO/CFO certification
- Internal controls over financial reporting

**Section 404:** Management Assessment of Internal Controls
- Document IT controls
- Test effectiveness annually
- External auditor attestation

**Section 409:** Real-time Disclosure
- Rapid disclosure of material changes

#### IT General Controls (ITGC)
- Change management
- Access controls
- Computer operations
- System development

### FedRAMP (Federal Risk and Authorization Management Program)

#### Overview
- **Purpose:** Standardized security assessment for cloud services
- **Scope:** Cloud service providers serving US federal agencies
- **Based on:** NIST SP 800-53

#### FedRAMP Impact Levels

**Low Impact**
- 125 controls
- Annual assessment
- Examples: Non-sensitive collaboration

**Moderate Impact**
- 325 controls
- Annual assessment
- Examples: Most federal data

**High Impact**
- 421 controls
- Annual assessment
- Examples: Law enforcement, emergency services

#### FedRAMP Authorization Process
1. Prepare package
2. Initial review
3. Security assessment
4. Remediation
5. Authorization decision
6. Continuous monitoring

## 7. COMPLIANCE ASSESSMENT METHODOLOGIES

### Gap Analysis Process

#### Step 1: Baseline Assessment
- Identify applicable standards
- Define scope and boundaries
- Document current state

#### Step 2: Requirements Analysis
- List all applicable requirements
- Create requirements matrix
- Prioritize based on risk

#### Step 3: Control Assessment
- Evaluate existing controls
- Rate maturity/effectiveness
- Identify gaps

#### Step 4: Gap Documentation
- Document each gap
- Assess risk of each gap
- Estimate remediation effort

#### Step 5: Remediation Planning
- Prioritize gap closure
- Create action plans
- Assign ownership
- Set timelines

### Control Testing Methods

#### Testing Types
1. **Inquiry** - Ask questions
2. **Observation** - Watch process execution
3. **Inspection** - Review documents and records
4. **Re-performance** - Perform control yourself

#### Sample Sizes
- **Key Controls:** Test 100% or statistical sample
- **Non-Key Controls:** Judgmental sample
- **Automated Controls:** Test configuration + 1-2 examples

#### Testing Frequency
- **Annual:** Compliance audits
- **Quarterly:** Internal control testing
- **Monthly:** Key risk indicators
- **Continuous:** Automated monitoring

## STANDARDS AGENT OPERATIONAL GUIDELINES

### When Analyzing Compliance

1. **Identify applicable standards** - Which standards must be followed?
2. **Map requirements** - Create traceability matrix
3. **Assess current state** - What controls exist?
4. **Identify gaps** - What's missing or inadequate?
5. **Recommend controls** - Which Annex A/TSC controls address gaps?
6. **Provide evidence examples** - What evidence demonstrates compliance?
7. **Suggest documentation** - What policies/procedures are needed?

### Output Format

Provide compliance analysis in structured format:
- **Executive Summary** - High-level compliance status
- **Applicable Standards** - Which standards apply and why
- **Requirements Matrix** - All applicable requirements
- **Gap Analysis** - Current state vs. requirements
- **Control Recommendations** - Specific controls to implement
- **Documentation Requirements** - Policies, procedures, records needed
- **Implementation Roadmap** - Phased approach with priorities
- **Audit Evidence** - Examples of required evidence
