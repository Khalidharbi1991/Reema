## Summary

**Open Critical 0, open High 0. No finding here blocks merging `fix/snafi-settings-push` to main.** Khalid decides.

Answers to the five questions Ahmad asked:

1. **Nothing private reaches the screen in an error.** The screen shows only a fixed, translated step text and an optional detail. The detail can only be one of these:
   - "timed out", "not active" or "refused";
   - the browser's permission value;
   - an error's `name`, and only if it matches `/^[A-Za-z]{1,40}$/`. Otherwise it shows "error".

   An error's `message` is never rendered or logged, and React escapes the text. See SEC-143.
2. **Self-registration can only register this site's own `/sw.js`.** The call is the same one `ServiceWorkerRegister` already makes. Browsers refuse a cross-origin worker script, and the CSP has `worker-src 'self'` and `base-uri 'self'`. See SEC-144.
3. **`save_push_subscription` and the push-host allow list (SEC-126 and the endpoint rule) are unchanged.** They are still the only way an address is stored. The diff does not touch the migrations, `types.ts` (`checkPushKeys`), the mailbox adapter, or the `savePushSubscription` and `removePushSubscription` actions. See SEC-146.
4. **Removing `revalidatePath("/settings")` has no security effect.** See SEC-145.
5. **The time limits can leave a half-done state, but none is serious.** A time limit stops waiting on the screen; it does not cancel the request. So a push address or a settings save can land after the screen said it failed (SEC-141, Low). The separate busy flags also allow a race in which push ends up switched on while the screen shows Off (SEC-140, Low). A late subscription at the browser's push service on its own stores and sends nothing (SEC-142, Info).

   In every case the address still passes the allow list, the lock screen still shows only the generic text, and the daily cap and the quiet time after each adhan still apply. No private text is sent anywhere because of these states. Neither Low blocks the merge.

## Notes on the tests (not findings)

The new tests in `tests/settings-push-livebug.test.tsx` cover: a permission prompt or push service that never answers, a blocked permission, registering a worker that never starts, keeping only an error's name, unsubscribing on a server refusal, Save working while On waits, and a Save that never answers. They use plain promises, not real server actions, so they do not show the one-at-a-time behaviour behind SEC-140 and SEC-141 (d). None of them covers a request that lands after its time limit (SEC-141) or the Off-then-Save race (SEC-140). I did not run them.
