**Results:**
- **SEC-106: closed.** `html_to_text` is a single forward pass. Each step finds the next `<`, then the next `>`, and moves `i` past it. The tag-name regex is anchored and bounded to 40 characters. A `script`, `style`, `head` or `title` tag jumps forward to its closing tag, or stops if there is none. An unclosed `<` ends the loop. So the work grows with the length of the input, and the input is cut to 1,000,000 characters first. The two `re.sub` passes at the end are linear: `[ \t\r\f\v]+` cannot backtrack badly, and `\n[ \n]*\n` succeeds from each run's first newline. Gmail uses the same function, so its copy of the old pattern is gone too. The timing test covers the cases I named (200,000 `<script>`, 1,000,000 `<`) plus three more. Its 5-second bound is generous, but it would catch a quadratic regression. One small point: text inside a comment after its first `>` (for example `<!-- a > b -->`) is kept as text. It goes only to the brain as untrusted data anyway, so this is harmless.
- **SEC-107: closed.** `_date` treats a naive time as UTC. `important_unread` also makes the parsed time aware and catches `TypeError`. `build_row` now runs each source in its own `try/except Exception`, sets just that source to `error`, and logs only the source name with "retryable", "refused" or the exception's type name, never its text. The closures capture `row`, `yahoo`, `tasks`, `now` and `tz`, which are all set before the loop, so late binding does no harm. Tests cover a `-0000` Date and a `TypeError` and `KeyError` from two sources. **Left as optional (Info):** a row that breaks 0007's size checks still fails the whole upsert. The task titles were not shortened.
- **SEC-108: closed.** `values()` now calls `_maybe_reload(RELOAD_SECONDS)` every time. The first call reloads at once, and later calls reload at most every 300 s, while connected too. A removed value then gives `NotConnected`. If Credential Manager cannot be read, the old values are kept (fail-open for removal). That is acceptable, and the docstring says so. `refused()` shares the reload timer, so right after a 5-minute reload a refusal does not re-read for 30 s. That only delays picking up a new password. Tests cover a removal seen on the first read and one seen within 5 minutes. The setup doc's `--remove` line is now accurate ("within five minutes" is in `credentials.py`).

What step 4 gets right, from the code I read (not verified by running anything):
- **IMAP injection:** every search value is sent as a quoted string, with `\` and `"` escaped and every control character refused (`_quote`), or as a counted UTF-8 literal. UIDs are digits from the server, and ids must match `y<digits>_<digits>` (with `\Z` since the fix). The folder names are fixed or come from the server's LIST, and they are quoted too.
- **Header injection:** subjects pass `CONTROL` (SEC-82). Addresses pass `EMAIL`. In-Reply-To and References from the replied-to email must match `<[^<>\s]{1,250}>`. `EmailMessage` refuses line breaks inside a value. Bcc goes on the envelope only.
- **Reading never marks mail read:** the Inbox is opened read-only (EXAMINE), and every fetch is `BODY.PEEK`. Only Drafts is ever opened read-write, and only to delete a draft.
- **Draft Undo deletes only that one draft:** the id must match `yd<validity>_<uid>`, the account and id prefix must agree, and Drafts' UIDVALIDITY must still match. The UID must exist, and the server must offer UIDPLUS. The delete is `UID STORE +FLAGS.SILENT (\Deleted)` followed by `UID EXPUNGE <that uid>`, so it never runs a plain EXPUNGE.
- **TLS and hosts:** `IMAP4_SSL` to `imap.mail.yahoo.com:993` and `SMTP_SSL` to `smtp.mail.yahoo.com:465`, both with `ssl.create_default_context()` (certificate and host name checked). The hosts are fixed in code, not taken from `worker.yaml`. Todoist accepts only `https://api.todoist.com` with no user and no port, refuses redirects, and sends the token only in the Authorization header.
- **Account routing:** the gate decides the account from the id (a reply goes from the account the email came from) and refuses a mismatch. `prepare` puts `account` and `from_address` into the card args, so the args hash binds them. The summary reads "Send from Yahoo (address) to …". At run time the send is refused if the Yahoo address changed after Approve.
- **An email or task cannot trigger a send or delete:** sends and deletes are Level 3 cards only, and the proof tests are repeated for Yahoo and for a task. What an email or task *can* still trigger is Level 2 (SEC-105).
- **Secrets:** no secret reaches the brain, a log line, Supabase or the repo. The adapters and `StoredLogin` have hidden `repr`s, and the error messages are fixed strings raised `from None`. The Today feed logs only statuses, and since the fix, exception type names. No new package is added (standard library only), and the web app gets no new key.
- **`today_feed`:** RLS and grants unchanged in effect (select own row; only `service_role` writes). There are size and shape checks on `emails` (10) and `tasks` (10), and status checks on both new columns. React renders every field as text.

## Answers to the points Ahmad named (first pass; still true after the re-check)

1. **IMAP command injection:** none found. Search words become quoted strings (control characters refused, `\` and `"` escaped) or one counted UTF-8 literal; any further non-ASCII words are matched locally. Keys come from a fixed list, dates are built by code, UIDs are digits, and folder names are quoted.
2. **Header injection in drafts and sends:** none found. Subject passes `CONTROL`, addresses pass `EMAIL` (now with `\Z`), reply headers have a strict pattern, `EmailMessage` refuses line breaks inside a value, and Bcc goes on the envelope only.
3. **Reading never marks mail read:** yes. EXAMINE (`readonly=True`) for the Inbox, `BODY.PEEK` for every fetch, and the Today feed fetches headers only.
4. **Draft Undo deletes only that draft:** yes, and only with UIDPLUS (`UID STORE` then `UID EXPUNGE <uid>`), after checking the account, the id form, UIDVALIDITY and that the UID exists.
5. **TLS and fixed hosts:** yes, for IMAP, SMTP and Todoist. Todoist refuses redirects and sends the token only in the header (SEC-16 note). The proxy point is SEC-68.
6. **Sending from a different account than the card shows:** not possible as far as I can see. The account and `from_address` are in the hashed card args, the gate re-checks the account against `in_reply_to` on resume, the run uses exactly the card's args, and the address is compared again before the send.
7. **Honesty account rule:** works for the forms it knows, Arabic prefixes and Google included since the fix. What is left is SEC-109 (Info).
8. **New data in logs, Supabase or the brain:** no secrets anywhere. Logs get statuses, fixed messages and, since the fix, exception type names. Supabase, backups and the brain get Yahoo bodies, task text and Khalid's Yahoo address, as described in SEC-110, SEC-113 and the SEC-65 note.
9. **`today_feed` columns and RLS:** sound (select own row; only `service_role` writes; shape, size and status checks). The availability point (SEC-107) is closed.
