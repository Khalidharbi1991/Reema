## This round: checked, no finding

- **Download, order and failure handling:** the folder is locked (line 66, exit code checked) before `downloads` is created, so the file is written into a folder only Administrators and SYSTEM can change (on a first deploy, see SEC-36 (1) otherwise). HTTPS with TLS 1.2 and the default certificate check. The hash is checked on every path, including the cached copy, before the old `python` folder is deleted, so a bad download leaves the earlier Python in place. A mismatch deletes the file and throws with the actual hash. No step after a failure runs, since `$ErrorActionPreference = "Stop"` and pip's exit code is checked.
- **Extraction:** the target folder is deleted first and unpacked fresh, so nothing from an earlier Python survives. `ZipFile.ExtractToDirectory` in .NET refuses entries that would land outside the destination, and the package's bytes are pinned by the hash in any case. The NuGet extras (`[Content_Types].xml`, `_rels`, `package\`, `python.nuspec`) are left in `python\`; they are not code and are locked like the rest. A half-finished extraction throws and stops the deploy (the worker then has no Python, which fails closed).
- **pip as administrator:** pip runs from the fresh, hash-checked Python with `-I`, so the repo folder (the current folder of the admin session) is not on `sys.path` and a planted `pip.py` there cannot run. `--require-hashes --only-binary=:all: --no-deps` is kept, with exactly the same two pinned wheels. The pip 25.0.1 inside the package is used only for wheels, so its known sdist and tar issues do not apply. What pip still reads is SEC-40.
- **Permissions on the new folders:** `python` and `downloads` are created by the elevated session under the locked folder and inherit its (OI)(CI) entries. Lines 107-108 reset every child to inherit and set Administrators as owner, after pip and after the old venv is removed. `snafi-worker` and Khalid get read and run only.
- **Launcher and task:** both use the private `python.exe`/`pythonw.exe` with `-I`; the task still runs as `snafi-worker`, limited, with `C:\SnafiWorker` as working folder. Nothing else changed in them.
- **Secrets, logs and the brain:** nothing new is logged, printed or sent. No worker code changed apart from the `set_secrets` docstring.
- **Packages:** no new Python package. The Python runtime is now a pinned NuGet package instead of a machine-wide install.
- **Web app:** not touched by this diff. Only the publishable key is used, as before.
