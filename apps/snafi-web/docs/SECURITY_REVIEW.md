(3) The stderr line can carry account or token text into the failed record and the console (SEC-46). SEC-27 is still the main design risk. **It should be treated as High, and fixed, before step 3 puts email or any other outside content in front of agy.**

## This round: checked, no finding

- **The prompt stays off the command line.** `argv()` holds only fixed flags, the model, the time limit, and the settings and schema JSON. The prompt goes only on stdin as one `{"event":"user",...}` line (`agy.py:347-349`). `--print=` carries an empty value, so nothing of Khalid's chat or the data blocks is put in agy's command line, where other tools on the PC could see it.
- **What `--print=` could do, and what catches it.** I cannot run agy, so all of this is **verified only by the live proof**. (a) agy reads the stdin event as the prompt, as intended: the proof can pass. (b) agy takes the empty string as the whole prompt and ignores stdin: the normal attempt fails ("did not say ready" or "not usable"), and write, command and read fail on `must_refuse`. (c) agy treats an empty `--print=` as "no print mode" and starts its interactive mode: with a pipe and no window it prints no stream-json init, so "agy started no session" or "agy timed out" fails every attempt. (d) agy reads `--print=` as a bare `--print` and eats `--model`: the model name becomes a positional argument or an error, and the case is caught as in (b) or (c). In none of these does the lockdown get weaker without the proof failing, because `--settings` (with the deny list and `toolPermission: strict`), `--mode plan` and the tripwire do not depend on how the prompt is read. One case the proof cannot rule out: agy joining the stdin prompt with text from some other source (for example an instruction file it finds itself). That is not changed by this diff (see "Not reviewed").
- **The proof cannot be passed by mistake after this change.** `FLAGS` is in `fingerprint()` (`agy.py:85`), so the proof record from before no longer matches, `preflight()` raises `BrainNotReady`, and the brain stays paused until a new proof passes. A failed proof still deletes any older pass (`agy_proof.py:137`).
- **The new "no session" line only adds a problem**, so it can only fail an attempt, never pass one. The permission-mode problem is still added after it. The full stderr still goes into `seen`, so a code echoed on stderr still counts as "came back" (fails safe).
