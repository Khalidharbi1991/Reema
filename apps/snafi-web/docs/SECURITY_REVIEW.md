## This round: checked, no finding

- **Proof flow:** every attempt still checks the mode, timeouts, succeeded tools, files in the workspace, the three marker files and the three random codes (in the result and stderr). A failed proof still deletes an older pass, and the install fingerprint is still taken before and after.
- **Injection attempt:** attempt 6 uses `transcript` and `data_block` from the worker's own code, so it tests the format the worker really sends. It does not require a refusal (a model that ignores the data is a pass), which is right for this attempt.
- **`EMPTY_LINES`:** the new pattern is anchored (`^...$`) and matches only lower-case words separated by single spaces and ending in `...`. A listing line with a name, a type or a path does not match.
- **Deploy order:** the task is stopped before anything changes. The venv is removed before pip runs. `Remove-Item` throws on a locked file (`$ErrorActionPreference = "Stop"`), so a deploy cannot go on with a half-removed venv.
- **Tests:** the `test_snafi_worker_agy.py` diff replaces the whole file, but the old tests are all still there (only the expected count changes from 6 to 7, the "did not try" text, and fake tool names chosen per attempt). The new tests cover each part of the SEC-28 fix listed above. The deploy test checks the owner commands and their order.
- **Secrets and logs:** nothing new is logged or printed. The proof's problem texts hold tool kinds and modes, never codes or prompt text.
- **Network and packages:** nothing new. No package added.
- **Web app:** not touched by this diff. Only the publishable key is used, as before.
