"Dormant" means the finding is in the agy code only, which does not run while `worker.yaml` names `gemini_api`. It stays open because one line switches agy back on.

**My recommendation:** safe to merge. The Gemini brain is tool-free by construction: the request body may hold only `systemInstruction`, `contents` and `generationConfig` (`gemini_api.py:20,85-86`), so no tools, function declarations, Google Search grounding, code execution or URL context can be sent. Any reply part other than text is rejected (`gemini_api.py:112-114`). The search_web-style leak that failed agy needs a tool, and the API runs no tool it was not given. Nothing agy-specific runs when `gemini_api` is configured, and old agy state cannot weaken the Gemini brain (at worst a leftover pause file stops it, which fails closed). The key goes only in a header and is never in a URL, error, log, backup or the action log. The main new risk is money: the brain is now a paid call, and **nothing in the worker limits how many calls it makes per day**. A stolen session (SEC-4) or a burst of duplicate jobs (SEC-18) can spend up to whatever stops Google's billing. A Cloud Billing budget only sends alerts and does not stop spending. Before go-live, Khalid should set a hard stop he has checked (a per-day request quota on the key's project), and the worker should get its own daily cap (SEC-47). Also: use a new key made for this purpose, not the one stored under Khalid's own user on Nov 9 (SEC-48).

## This round: checked

- **gemini_api is tool-free (no finding).** `build_request` builds exactly `systemInstruction`, `contents` and `generationConfig`, and refuses any other top-level key (`gemini_api.py:20,75-86`). `generationConfig` holds only the JSON mime type, the response schema, `maxOutputTokens` and `temperature`. Tools, `toolConfig`, function declarations, Google Search grounding, code execution and URL context are all top-level `tools` or `toolConfig` entries in this API, so none can be sent. The API does not turn on tools that the request did not ask for, and there is no project setting that adds them by default. Each part of the reply must have only `text`, `thought` or `thoughtSignature` (`gemini_api.py:22,112-114`). A `functionCall`, `executableCode` or `codeExecutionResult` part is refused, as final, and `MALFORMED_FUNCTION_CALL` or `UNEXPECTED_TOOL_CALL` finish reasons are refused (`gemini_api.py:109-110`). Thoughts are dropped from the text. Even if a tool call came back, nothing on the PC would run it, because only the gate runs registered tools from `actions`.
