| SEC-12 | Medium | **Closed** (this review) | `src/snafi_worker/engine.py:192-229,245-262`, `src/snafi_worker/store/supabase_rest.py` (`update_if`), `supabase/migrations/0003_approvals_once.sql:12-14` | An approved Level 3 action could run twice after a retry, a database error or a timeout. | **Re-check, verified in code:** `0003` adds `executing` to the status check. `approval_resume` returns early (it never raises, so nothing is retried) for `executing`, `executed` and `failed`. In the Supabase store, `update_if` is a single `PATCH ?id=eq.X&status=eq.approved` with `return=representation`. ## This round: checked, no finding

- **Migration 0003:** it runs in one transaction. It only drops and re-adds the approvals status check, adds two columns with safe defaults (existing pending cards get an empty hash and can only be rejected), and replaces `decide_approval`. No grant on `approvals` changes. The app still has no update or delete, and a test shows that the app cannot set `executing` directly. `expires_at` is not insertable by the app. The old function signature is dropped, so no unbound Approve path is left.
- **Web app:** only the publishable key is used. No new cookie, redirect, `dangerouslySetInnerHTML` or outside call was added. `decideApproval` returns only a status string to the client. `effectiveStatus` is display-only, and the database decides expiry. Preview and the memory mailbox mirror the hash and expiry checks.
- **Worker secrets handling:** `Secrets` still hides values in `repr` and `str`. Error messages name the credential, never its value. `--check` and `set_secrets --status` print names only. The test that touches the real Credential Manager uses a unique `REEMA-Snafi-TEST-<uuid>:` prefix and deletes its entry in `finally`. The brain gets no secret. The store sends the key only in headers, as before.
- **Brain adapter:** not changed in this diff. Text only, no tools or tool config, and function-call replies rejected, as reviewed in step 2.
- **Permission gate and four levels:** unchanged. `approval_resume` still re-runs the gate on the stored tool and args and requires Level 3.
- **Honesty check:** unchanged. It still runs on the brain's reply and on the follow-up.
- **Backups:** the signing key is never written to the backup or the logs. The HMAC is computed over sorted-key JSON of the manifest without `signature`. Pruning and the `.part` temp file are unchanged.
- **Task Scheduler script:** not changed in this diff (see SEC-19 and SEC-25).
- **Packages:** none added on either side. The worker uses `ctypes`, `hmac`, `getpass` and `secrets` from the standard library.
- **Network:** no new outside call. `set_secrets` makes no network call; it only parses the values.
- **AGENTS.md:** the secrets rule now names Credential Manager and the guard as a backstop, which matches the code.
