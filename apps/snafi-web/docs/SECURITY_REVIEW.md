**My answers to Ahmad's first-pass questions** (unchanged except where marked):

1. **PKCE, state and loopback in `connect.py`:** sound.
   - PKCE uses S256 with an 86-character verifier from `secrets`.
   - The state is 32 random bytes, compared with `hmac.compare_digest` before anything else.
   - The listener binds `127.0.0.1` only, on a random port, for at most 300 seconds, and handles one answer. Its request line is never logged, and the refresh token is never printed.
   - All four scopes must be granted, or nothing is stored.
   - What is left is Info (SEC-85): any request to `/` with a wrong state ends the run (denial of service only), and nothing shows which Google account was connected.
2. **Can untrusted content reach an action without Khalid?** Sends, invites and deletes cannot: they always become a card. Level 2 drafts and own-calendar events can, both in the follow-up call (SEC-80, Medium) and in later turns (SEC-81, Low).
3. **Header injection and recipient smuggling:** recipients cannot be smuggled. `_text_list` strips each address, and the `EMAIL` pattern allows no comma, space, `<`, `>`, `"` or line break inside. Each address therefore stays one recipient. The cap counts To, Cc and Bcc together, after removing duplicates without regard to case. **Re-check:** the bare-LF gap in the one-line check is fixed (SEC-82).
4. **Drive query escaping:** correct for Drive's query grammar. Backslash is escaped first, then the single quote. The search is read-only. No finding.
5. **What reaches Supabase:** more than the docs said (SEC-83, Low). The full draft and email bodies are in `approvals.args` and `action_log.args`. Senders, subjects, event titles and file names are in `action_log.summary` and the chat's outcome lines. Ahmad's own summary of an email is in the chat reply. No token or key goes there. **Re-check:** the worker README now says this; the code is unchanged.
6. **`today_feed` RLS and constraints:** correct. There are no grants for `anon`. `authenticated` gets select only, through a policy for its own row, with RLS forced. Writes come only from the service role. The size, count and status checks are in place, and the web app keeps only known fields, cut to size. React escapes everything shown. Bidi and invisible characters in senders and subjects are the SEC-26 family (note added there). No new row.
7. **The reload path in `GoogleAuth`:** safe, but a disconnect does not reach the running worker (SEC-84, Low).
8. **The guard additions:** they work for what they name, including Windows `\` paths. **Re-check:** they now also cover the SEC-79 path (closed).
