## Summary (after the re-check of commit 7d62a24)

**Open Critical 0, open High 0. Nothing in this review blocks merging `feat/snafi-memory-family` to main.** Khalid decides.

**Re-check of the five fixes:**
- **SEC-199: closed (re-reviewed).** All three copies now apply NFKC and drop the zero-width characters, the soft hyphen and U+2060 and U+FEFF. They map ی and ک, and allow up to three of ` ./()-` between digits. They also refuse `password…`/`passwd…`/`passcode…` with anything glued after them, `pwd`, `pin` and `otp` followed by digits, the door, alarm, gate and safe codes, and the Arabic forms I listed. Every example from my row is in the shared fixture. Smaller gaps that remain are in the new **SEC-214 (Low)**.
- **SEC-200: closed (re-reviewed).** A reply posted after outside content now carries `meta.read_outside`. While such a reply is among the last 20 messages, a memory save runs only if at least half its counted words appear in Khalid's current message. Khalid's "ok" or "thanks" after a hostile email can no longer save the email's words. The app cannot set or clear that flag: it can insert only `role = 'user'` messages, and the engine's `_tainted` and `_message` keys live on the job object in memory, not in the job row. What is left: a padded save can still pass the half-rule (new **SEC-215, Low**), and the flag depends on what the read tools return (new **SEC-216, Info**).
- **SEC-201: closed (re-reviewed); part (5) not done.** New `snafi_scrub_memory_text` is security definer, `search_path = ''`, revoked from `public, anon, authenticated`, and acts only on `user_id = p_user`. On every Forget it blanks every `search_memory`, `list_family` and `list_facts` entry. It also blanks every `add_*` entry whose body, name or person matches the forgotten text after normalising: "already saved" entries, failed saves and saves that were undone. `forget_fact` and `forget_family_member` pass the text; `forget_family_date` blanks the reads. A worker Undo of a memory save now blanks that entry's args, result and summary. The migration scrubs the log for the soft-deleted facts before deleting them, and every function it calls is defined before the `do` block. Part (5) (the About me page's note about cards) is not done; it is wording only, for Khalid.
- **SEC-202: closed (re-reviewed).** In `_act`, anything other than a memory save stops at 5 per brain call, so 8 applies only to memory saves (still capped at 3, or 6 in the interview). Each call has its own count, so one message with a follow-up allows 5 + 5, the same as before step 6.
- **SEC-204: partly fixed, stays open (Low).** Facts that fail the guard are left out of `memory_turn.items`, so they are no longer in the memory block or the "I don't remember" recall. Two other paths still read all facts:
  - `search_memory`, through `memory/tools.py` `_search` → `all_items`. Its result line goes into chat and, from there, back to the brain as earlier results.
  - The gift-ideas data, through `scheduler.family_week` → `memory.facts`.

## Answers to Ahmad's first-round points, in short

1. **Migration 0010 is sound as access control.**
   - `family_members`, `family_dates` and `interview_state` have RLS enabled and forced, with one select-own policy each. All rights are revoked from `anon` and `authenticated`, and only `select` is granted back. The app has no direct write on them or on `facts` (the test says so; I did not run it).
   - The save and forget functions are `security definer` with `search_path = ''`. They take the user only from `auth.uid()` and refuse null, touch only `where ... user_id = uid`, and check that a date's person is the caller's own. They are revoked from `public, anon` and granted to `authenticated`.
   - `snafi_scrub_log` and, after the fix, `snafi_scrub_memory_text` are revoked from `public, anon, authenticated` and scrub only `where user_id = p_user`.
   - The no-secrets rule is a CHECK on every new or changed row for every writer, `service_role` included. It is `NOT VALID` only for facts already there (SEC-204).
2. **Migration 0011 is sound** (SEC-212).
3. **Worker:**
   - Memory goes to the brain only inside `<data source="memory">`, never as a turn or in the system prompt.
   - Memory saves are refused in the follow-up after outside content and, since 7d62a24, must be grounded while such a reply is in the recent chat.
   - At most 3 saves a message (6 in the interview), counted in code. Saves are Level 2 with an Undo that hard-deletes, and since 7d62a24 the Undo also blanks the log entry.
   - The brain has no forget tool.
   - Interview commands are matched in code with no brain call.
   - Family reminders are kind `reminder`, never twice, never counted to the cap, go through `Notifier.deliver` (prayer quiet applies), and show fixed text on the lock screen.
   - Gift ideas: see SEC-209.
   - The invite goes out once.
   - Backup schema 7 holds the new tables and never `cards` or `notifications`.
   - Restore drops soft-deleted facts and facts that fail the guard, but brings back forgotten items (SEC-203).
4. **Web app:** see SEC-211.
5. **Family members (later):** another signed-in user cannot read or change Khalid's memory by any path I found. Two defence-in-depth gaps are in SEC-205.
